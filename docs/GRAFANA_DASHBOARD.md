# Grafana SOC Monitoring Dashboard

## 1. Overview

This project includes a Grafana-based SOC monitoring dashboard connected to the Wazuh Indexer through an OpenSearch data source.

The dashboard provides centralized visibility into security alerts generated by monitored endpoints. It helps a SOC analyst monitor alert activity, identify frequently triggered detection rules, and investigate authentication-related events.

## 2. Architecture

The monitoring workflow follows this architecture:

1. **Wazuh Agent:** Collects endpoint security events.
2. **Wazuh Manager:** Analyses events and generates security alerts.
3. **Wazuh Indexer (OpenSearch):** Stores and indexes Wazuh alerts.
4. **Grafana:** Queries OpenSearch and visualizes security events.
5. **Read-only account:** Grafana uses a dedicated OpenSearch account and role for accessing alert data.

Grafana retrieves alert data from OpenSearch; it does not read directly from the Python forwarder.

## 4. Authentication Monitoring

Authentication monitoring uses Wazuh alert data to observe successful and unsuccessful login activity.

### 4.1 Failed Login Detection

Query:

```text
rule.groups:authentication_failed
```

This query helps identify failed authentication events.

During lab testing, the following Wazuh rules were observed:

- **5710:** Invalid or non-existent SSH user.
- **5503:** PAM login failure.
- **2502:** Repeated missed password attempts.

### 4.2 SSH Brute-Force Monitoring

Query:

```text
rule.id:2502
```

This panel tracks events associated with Wazuh rule 2502, which detects repeated password failures.

### 4.3 Successful Login Monitoring

Query:

```text
rule.groups:authentication_success
```

This query provides visibility into successful authentication events.

### 4.4 Source IP Monitoring

Field:

```text
data.srcip
```

The dashboard groups failed-authentication alert events by source IP address.

During controlled SSH testing, `127.0.0.1` appeared as a source address. This represents loopback traffic from the local system, not evidence of an external attacker.

## 5. SOC Alert Investigation Workflow

A basic investigation workflow using this dashboard:

1. Review the total alert count and alert trends.
2. Identify higher-severity alerts.
3. Review recent security events.
4. Investigate frequently triggered Wazuh rules.
5. Compare successful and failed authentication activity.
6. Examine SSH brute-force-related alerts.
7. Check source IP addresses associated with suspicious authentication events.
8. Investigate the original event in Wazuh before determining whether it is malicious.

## 6. Technical Implementation

- Lucene queries
- Terms aggregation
- Date Histogram aggregation
- Dedicated read-only OpenSearch account and role

## 7. Security Considerations

- Alert counts represent matching alert documents, not necessarily unique attacks or incidents.
- A high alert count does not automatically indicate malicious activity.
- Wazuh rule levels help prioritize investigation but should not replace event analysis.
- Source IP addresses must be interpreted in context.
- Successful authentication does not automatically mean an account is uncompromised.
